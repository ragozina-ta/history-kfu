# Как мы делали сайт с помощью нейросети

Материал для рассказа на паре. Речь только про **создание сайта** (вёрстка, интерактивы, деплой), не про содержание методических материалов занятия.

---

## Коротко: что за проект и чем делали

Сайт — страница темы «Разговоры о важном» плюс несколько интерактивов:

- «Правда или ложь?»
- «Сопоставь события»
- «Хронологический конструктор»

Публикация — на **GitHub Pages**.

Основной инструмент — **Cursor** (AI-агент прямо в редакторе кода). Это не чат «напиши код в блокнот», а ассистент, который видит файлы проекта, правит HTML/CSS/JS, коммитит и пушит.

### Почему Cursor, а не «просто ChatGPT в браузере»

- код сразу попадает в репозиторий, без бесконечной копипасты;
- нейросеть видит уже готовые стили и повторяет тот же визуальный язык;
- удобно итерировать: «сломалось — поправь», «сделай лаконичнее»;
- деплой и git рядом с правками.

Другие нейросети для **самого сайта** почти не нужны: тексты материалов и PDF готовились отдельно; AI собирал оболочку страниц и логику интерактивов.

## Последовательность работы

### 1. База / каркас

Сначала появилась главная страница в стиле «Разговоры о важном» и один интерактив («Сопоставь события»). Дальше сайт наращивали поверх этого каркаса, а не собирали каждый раз с нуля.

**Вывод:** AI хорошо работает, когда есть образец — шрифты, цвета, кнопки «Открыть / Скачать».

### 2. Публикация: GitHub Pages

**Промпт по смыслу:** добавить GitHub Pages.

**Что сделала нейросеть:** workflow деплоя, файл `.nojekyll`, сайт по адресу вида `username.github.io/history-kfu`.

**Почему так:** без деплоя сайт только локально; Pages — простой хостинг для статики (HTML/CSS/JS без бэкенда).

### 3. Интерактив «Правда или ложь?»

**Промпт:** отдельная страница, заголовок, 9 карточек, утверждение / правда–ложь / объяснение; лицо одного цвета, оборот зелёный или красный.

**Что важно в промпте:** не абстрактное «сделай квиз», а **конкретная механика и готовые тексты** карточек.

**Почему снова Cursor:** тот же визуальный стиль, что у «Сопоставь события» (тёмный фон, шрифт PT Root UI, фиолетовые акценты).

### 4. Связка с главной

**Промпт:** связать страницу интерактива с главной.

В блоке материалов появились пункты с кнопкой «Открыть» на HTML-страницы игр.

### 5. Наполнение оболочки (проводка файлов и ссылок)

Промпты вроде:

- положи PDF / картинку в нужную папку и прикрепи в нужном месте;
- тема занятия = …;
- добавь баннер;
- ссылка «Главная» → [разговорыоважном.рф](https://разговорыоважном.рф/);
- кнопка-конверт → Яндекс.Форма;
- видео с кнопкой «Смотреть»;
- ссылка на музей «Белем».

**Паттерн удачного запроса:** файл или ссылка + куда в интерфейсе + действие (открыть / скачать / смотреть).

### 6. Доводка интерфейса

Примеры итераций:

- убери серую рамку у баннера, скругли углы;
- слева слишком пусто — сделай лаконичнее;
- баннер оставь как было, только добавь «Тема занятия» и оформи текстовый блок;
- слишком большой отступ под баннером.

**Вывод:** AI не «угадывает вкус» с первого раза. Работает цикл **запрос → взгляд на результат → уточнение**.

### 7. Дисциплина: коммит после каждого изменения

**Промпт:** на каждое изменение — коммит и пуш; без служебных подписей вроде Co-authored-by Cursor.

Это уже не про UI, а про процесс: история git = лог шагов проекта.

### 8. Интерактив «Хронологический конструктор»

**Промпт:** горизонтальная лента из 9 точек без годов → стикеры событий → «Проверить» (ошибки красные) → через несколько секунд правильный порядок, сверху появляются годы.

Потом доводка: текст вылезает из стикера — перенос слов / меньший шрифт.

**Снова тот же принцип:** сначала механика и данные, потом полировка.

## Как формулировали промпты

Удачный запрос обычно содержал:

1. **Что** — отдельная страница или блок на главной  
2. **Как выглядит** — заголовок, цвета, оборот карточки  
3. **Как работает** — клик, drag-and-drop, проверка  
4. **Данные** — готовые тексты, ссылки, файлы  
5. **Куда встроить** — «в материалы для занятия», «кнопка конверта»

Слабый промпт выглядел бы так: «сделай красивый образовательный сайт» — без структуры и без привязки к уже существующему макету.

## Роли: человек и нейросеть

| Человек | Нейросеть (Cursor) |
|--------|---------------------|
| Тема, смысл занятия, PDF, видео, ссылки | Вёрстка, стили, JS интерактивов |
| Критика UI («пусто», «много отступа») | Правки HTML/CSS по замечаниям |
| Решение «публикуем на Pages» | Workflow, папка `materials/` |
| Проверка «так ли должно работать» | Flip-карточки, drag-and-drop, проверка ответов |

Нейросеть — ускоритель реализации. **Сценарий и материалы занятия** остаются за авторами.

## Ультракоротко (1–2 минуты)

Сайт собрали в Cursor: AI пишет код прямо в проекте. Сначала каркас страницы и один интерактив, потом GitHub Pages. Дальше по промптам добавляли страницы игр, ссылки и файлы на главной. Дизайн правили итерациями — отступы, баннер, блок заголовка. Интерактивы описывали жёстко: механика плюс тексты. После каждого шага — коммит в git. AI отвечал за код и деплой; содержание занятия — наше.

## Возможные вопросы

**«Это же всё сделала нейросеть?»**  
Нет. Механику и тексты заданий задавали мы; AI кодировал. Без технического задания получился бы другой сайт.

**«Почему не конструктор вроде Tilda?»**  
Нужны свои интерактивы (перетаскивание, переворот карточек) и контроль вёрстки под «Разговоры о важном». Статика на GitHub удобна для учебного проекта.

**«Сложно ли повторить?»**  
Если есть образец страницы и чёткие промпты — да. Сложнее всего не «написать код», а **точно описать поведение** и потом довести интерфейс по фидбеку.
